# สำรองผลิตสด: ยึดยอดสั่งโรงงานที่ยืนยันแล้ว

## พฤติกรรมที่แก้

- ANP180/181/182 คลังกรุงเทพ: ก่อนส่งโรงงาน กรอกยอดคงเหลือและสำรอง แล้วกด “ยืนยันสั่งโรงงานแล้ว”
- ยอดรับเพิ่มได้ = ยอดผลิตที่ยืนยัน + ของคงเหลือที่บันทึก − ความต้องการปัจจุบันของวันนั้น รวมรายการพิเศษตามสูตรเดิม
- ออเดอร์เพิ่ม/แก้เพิ่มหักสำรอง การลด/ยกเลิกคืนสำรอง และการโอนคลังเปลี่ยนความต้องการตามคลังจริง
- ใบสั่งโรงงานวันเดียวใช้ยอดผลิตที่บันทึก ไม่คำนวณผลิตเพิ่มเองเมื่อมีออเดอร์เพิ่ม
- ปุ่ม “สั่งผลิตเพิ่ม” รับเฉพาะจำนวนเพิ่มที่สั่งโรงงานจริง เพิ่มกำลังรับออเดอร์โดยคงยอดออเดอร์เริ่มต้น/ของคงเหลือเดิม พร้อมประวัติการเพิ่ม
- ใช้ข้อมูลที่เคยบันทึกไว้เป็นยอดยืนยันเดิม ไม่เปลี่ยนข้อมูลวันที่ 9 ต.ค. หรือสร้างรายการสั่งเพิ่มเอง
- บันทึกสามสินค้าในธุรกรรมเดียว ตรวจรุ่นข้อมูลก่อนบันทึก กันคนกดซ้ำ/ข้อมูลเก่าและการทับ metadata ส่วนอื่น
- หน้าสำรองตรวจข้อมูลทุก 30 วินาทีเมื่อเปิดอยู่ และเมื่อกลับเข้าแอป; หยุดระหว่างเปิดหน้ากรอกข้อมูล
- รายการล่าสุดแสดง “ยอดปัจจุบัน” ของรายการที่แก้หลังยืนยัน แทนการอ้างว่าปริมาณทั้งหมดคือจำนวนเพิ่ม และกรองตามคลัง/เวลายืนยันของแต่ละสินค้า

## ตรวจแล้ว

- PostgreSQL 18 ในฐานข้อมูลทดสอบแยก: ยืนยันครั้งแรก, ใช้สำรอง, ลด/ยกเลิกออเดอร์, เกินกำลัง, สั่งผลิตเพิ่ม, ข้อมูลเก่า/กดซ้ำ, ข้อมูลซ้ำ, ข้ามองค์กร, rollback ทั้งชุดเมื่อแถวสุดท้ายผิด, สิทธิ์ RPC เฉพาะ service_role
- ทดสอบหน้าใช้งาน desktop/mobile ด้วย Chrome: ยืนยันยอดใหม่, กรอกจำนวนผลิตเพิ่ม, ห้ามบันทึกเพิ่มศูนย์, แสดงข้อผิดพลาดเมื่อส่งไม่สำเร็จ; ดักคำขอบันทึกทั้งหมด ไม่แก้ข้อมูลจริง
- ทดสอบสูตรสำรองเดิมผ่าน และ lint/build ผ่าน

## สถานะการเปิดใช้

เชื่อมต่อสำเร็จและติดตั้ง migration `20261009110356_confirm_factory_production.sql` ผ่าน Supabase แล้ว
Generated database types ใหม่ผ่าน Supabase และใช้ typed admin.rpc
ทดสอบกับ schema จริงใน transaction ที่ rollback ทั้งหมด: ยืนยันครั้งแรก, สั่งผลิตเพิ่ม, คง baseline เดิม, ข้อมูลเก่า/กดซ้ำ, ข้ามองค์กร และ rollback ทุกสินค้าหากแถวสุดท้ายผิด ผ่านทั้งหมด
ตรวจสิทธิ์ RPC: anon/authenticated เรียกไม่ได้ service_role เรียกได้
ตรวจ advisors แล้ว ไม่มี finding ของ function ใหม่ รายการเตือนส่วนอื่นเดิมอยู่นอกขอบเขตงานนี้
[แนวทางแก้รายการเตือนเดิม](https://supabase.com/docs/guides/database/database-linter)

ยอดเดิม 9 ต.ค. ที่เก็บไว้คงเดิม: ANP180 ผลิต340/คงเหลือ200, ANP181 ผลิต95/คงเหลือ0, ANP182 ผลิต75/คงเหลือ50

## ขอบเขตและข้อจำกัด

ใช้เฉพาะสามสินค้าที่มีหน้าสำรองเดิมของคลังกรุงเทพ ใบสั่งหลายวันยังใช้พฤติกรรมเดิม
ยังไม่ได้เทียบกับยอดผลิตจริงที่โรงงานรับทางแชทหรือเอกสาร เพราะระบบมีเพียงยอดที่ผู้ใช้บันทึก
ประวัติออเดอร์แสดงยอดรายการปัจจุบัน การลด/ลบย้อนหลังรายเหตุการณ์ไม่มี audit ของจำนวนก่อนแก้
ยอดติดลบเตือนว่าเกินกำลัง แต่ไม่ปิดกั้นการสร้างออเดอร์
