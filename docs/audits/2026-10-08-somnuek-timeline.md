## การตีความลำดับยอด

ลำดับที่โค้ดและหลักฐานรองรับคือ:
1. บันทึกครั้งแรกสร้างหัวก่อน แต่การเพิ่มสินค้าล้มเหลว
2. พยายามบันทึกอีกครั้ง โค้ดร้านเดิมบวกยอดหัวก่อน แล้วการเพิ่มสินค้าล้มเหลวอีก
3. ครั้งที่สินค้าสำเร็จ หัวบวกยอดอีก แต่มีสินค้าสำเร็จเพียงชุดเดียวและบิลคิดจากชุดนั้น

ภาพยอดหัว 915 → 1,830 → 2,745 เป็นการอนุมานจากโค้ดและผลรวมสุดท้าย
ไม่มี row history ยืนยันยอดหัวทุกช่วงโดยตรง จึงไม่ระบุว่าเป็นค่าจาก audit log
error logs ยืนยันการเพิ่มสินค้าล้มเหลว 2 ครั้ง แต่ไม่ยืนยันว่าใครกดปุ่มซ้ำด้วยมือ หรือโปรแกรม retry

## ความครบถ้วนและข้อจำกัด

- ค้นทั้งออเดอร์ของร้านที่มี order_date วันที่ 8 หรือ created_at/updated_at อยู่ในวันที่ 8 พบออเดอร์นี้รายการเดียว
- ค้น PostgreSQL logs วันที่ 8 เวลา 00:00–24:00 โดย order_id/เลขบิล พบ error สองรายการ ไม่ชนเพดาน 200 รายการ
- error logs ไม่บันทึกทุก UPDATE ที่สำเร็จ จึงใช้แทนประวัติแก้ไขครบทุกเวอร์ชันไม่ได้
- สินค้าปัจจุบันทั้งสามบรรทัดมี created_at = updated_at
- ไม่พบ inventory_movements ที่อ้าง order_id / delivery_note_id / reference_number ของออเดอร์นี้
  สินค้าทั้งสามเป็น mode fresh ในคลังกรุงเทพ จึงไม่ใช้การไม่มี movement สรุปว่าไม่มีการส่งของ
- ยอดค้างเดิม ยอดผ่อน และยอดคงเหลือของบิลเป็นศูนย์; ไม่มีหนี้เก่ามาทำให้ 915 ต่างจาก 2,745
- ไม่พบหลักฐานว่าบิลถูกพิมพ์กี่ครั้ง หรือรายการที่ส่งถึงร้านจริงเป็นเท่าไร
- โค้ดปัจจุบันแก้ค่า is_replacement แล้ว แต่การสะสมยอดหัวก่อนเพิ่มสินค้าและไม่มี transaction ยังเป็นช่องโหว่
- ไม่แก้ยอดจริง ไม่เปลี่ยนออเดอร์ ไม่ deploy
